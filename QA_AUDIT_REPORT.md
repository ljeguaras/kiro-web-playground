# QA Audit Report — kiro-web-playground

**Application:** `ljeguaras/kiro-web-playground`
**Type:** Next.js 16.2.4 (App Router, Turbopack) + React 19.2.4 + Tailwind CSS v4
**Build target:** Static prerender (`○` Static) of a single route `/` plus the framework `/_not-found`
**Audit method:** Static source review, `eslint`, `next build`, `npm audit`, live HTTP probing of the production server (`next start`), rendered-HTML/DOM analysis, and computed WCAG contrast analysis.

> **Scope reality check.** This repository is an essentially unmodified `create-next-app` starter. It contains **one page** (`app/page.tsx`), a root layout, global CSS, and five static SVGs. Large portions of the requested test matrix (forms, modals, dropdowns, tables, search, filters, pagination, CRUD, auth, sessions, tokens, protected routes) describe functionality that **does not exist in the application**. Those items are reported as **N/A — feature absent**, which is itself a finding for a product that is supposedly approaching production. The findings below are grounded in what the code and the running server actually do.

## 3. Detailed Bug Reports

### BUG-01 — Missing security headers (High / P1)
**Component:** HTTP response / `next.config.ts`
**Description:** The production server returns no security headers.
**Steps to reproduce:** `curl -s -D - -o /dev/null http://localhost:3000/`
**Expected:** Responses include `Content-Security-Policy`, `X-Frame-Options` (or CSP `frame-ancestors`), `Strict-Transport-Security`, `X-Content-Type-Options: nosniff`, `Referrer-Policy`, and `Permissions-Policy`.
**Actual:** Observed response headers were only `Vary`, `x-nextjs-cache`, `x-nextjs-prerender`, `x-nextjs-stale-time`, `X-Powered-By: Next.js`, `Cache-Control`, `ETag`, `Content-Type`, `Content-Length`, `Date`, `Connection`, `Keep-Alive`. No security headers present.
**Suggested fix:** Add a `headers()` block in `next.config.ts`:
```ts
async headers() {
  return [{
    source: '/:path*',
    headers: [
      { key: 'X-Content-Type-Options', value: 'nosniff' },
      { key: 'X-Frame-Options', value: 'DENY' },
      { key: 'Referrer-Policy', value: 'strict-origin-when-cross-origin' },
      { key: 'Permissions-Policy', value: 'camera=(), microphone=(), geolocation=()' },
      { key: 'Strict-Transport-Security', value: 'max-age=63072000; includeSubDomains; preload' },
      { key: 'Content-Security-Policy', value: "default-src 'self'; img-src 'self' data:; style-src 'self' 'unsafe-inline'; script-src 'self'" },
    ],
  }];
}
```

### BUG-02 — Placeholder SEO metadata (Medium / P2)
**Component:** `app/layout.tsx`
**Description:** `metadata` still carries create-next-app defaults.
**Steps to reproduce:** View page source `<head>`.
**Expected:** Product title and a meaningful description.
**Actual:** `<title>Create Next App</title>`, `<meta name="description" content="Generated by create next app">`.
**Suggested fix:** Replace with real product metadata; add OpenGraph/Twitter fields and `metadataBase`.

### BUG-03 — Dark-mode text contrast risk + weak landmark structure (High / P1)
**Component:** `app/page.tsx`, `app/globals.css`
**Description:** Computed WCAG contrast (verified programmatically):
| Pair | Ratio | WCAG AA (normal text ≥ 4.5) |
|---|---|---|
| Body `zinc-600 #52525b` on white | 7.73 | Pass |
| `h1` black on white | 21.0 | Pass |
| Link `zinc-950` on white | 19.9 | Pass |
| Dark-mode `zinc-400 #a1a1aa` on `#0a0a0a` | 7.72 | Pass |
| Base `zinc-600` on black (**if dark variant fails to apply**) | 2.56 | **Fail** |
The light/dark theme is driven purely by `prefers-color-scheme`; there is no manual toggle and no server/client reconciliation. The 2.56 ratio is the failure mode when the dark variant is not applied over the dark `globals.css` background. Combined with the near-total absence of landmarks (see BUG-04), screen-reader and low-vision UX is weak.
**Suggested fix:** Ensure dark text colors are the resolved default on dark backgrounds (don't rely solely on `dark:` utility ordering); add an explicit theme strategy.

### BUG-04 — Missing semantic landmarks (Medium / P2)
**Component:** `app/page.tsx`, `app/layout.tsx`
**Description:** Rendered DOM contains exactly `<main>: 1, <header>: 0, <nav>: 0, <footer>: 0, <h1>: 1`. The repository steering rule mandates **Semantic HTML for all layout sections**. There is no header, nav, or footer.
**Expected:** `<header>`, `<nav>`, `<main>`, `<footer>` as appropriate.
**Actual:** Only `<main>` exists.
**Suggested fix:** Wrap layout regions in semantic elements; this is also required by the project steering.

### BUG-05 — Fixed horizontal padding breaks small viewports (Medium / P2)
**Component:** `app/page.tsx`
**Description:** `<main className="... py-32 px-16 ...">`. `px-16` is 64px per side (128px total) with no responsive override. On a 320px viewport only ~192px remains for content, and `py-32` (128px top/bottom) pushes content far down.
**Steps to reproduce:** Render at 320px width (mobile).
**Expected:** Padding scales down on small screens (e.g. `px-6 sm:px-16`).
**Actual:** Fixed 64px padding at all breakpoints.
**Suggested fix:** Use responsive padding utilities, e.g. `px-6 py-12 sm:px-16 sm:py-32`. (Steering requires responsive Tailwind utilities.)

### BUG-06 — Inconsistent external-link rel/target handling (Medium / P2)
**Component:** `app/page.tsx`
**Description:** The two call-to-action anchors (Deploy Now, Documentation) use `target="_blank" rel="noopener noreferrer"`, but the two inline text links (Templates, Learning) are plain `<a href>` with neither. Inconsistent behavior and a minor security/UX gap (inline links navigate in-tab, buttons open new tabs, with no user cue).
**Suggested fix:** Standardize target/rel policy across all external links and signal new-tab behavior.

### BUG-07 — Dependency vulnerabilities (High / P1 for critical)
**Component:** dependency tree
**Description:** `npm audit` reports **16 vulnerabilities: 1 critical, 12 high, 2 moderate, 1 low.** Affected packages include `@babel/core` (arbitrary file read), `brace-expansion`/`braces`/`micromatch` (DoS), `browserslist`, `js-yaml`, `nanoid`, `@humanfs/node`, `baseline-browser-mapping`. Most are transitive via `eslint-config-next` tooling, but they ship in the lockfile.
**Suggested fix:** Run `npm audit fix`; evaluate `npm audit fix --force` (pulls `eslint-config-next@14.2.35`, a breaking change — test after). Pin and re-audit in CI.

### BUG-08 — Placeholder page content (Low / P3)
Body text is scaffolding ("To get started, edit the page.tsx file"). Not production content.

### BUG-09 — No skip-to-content link (Low / P3)
Keyboard users have no bypass link; add a visually-hidden "Skip to main content" anchor targeting `#main`.

### BUG-10 — No new-tab announcement for assistive tech (Low / P3)
External links lack `aria-label` / visible "(opens in new tab)" text.

### BUG-11 — `X-Powered-By` disclosure (Low / P3)
Server advertises `X-Powered-By: Next.js`. Set `poweredByHeader: false` in `next.config.ts`.

### BUG-12 — Default branding assets (Low / P3)
`favicon.ico`, `next.svg`, `vercel.svg`, `globe.svg`, `window.svg`, `file.svg` are all default template assets.

### BUG-13 — No OpenGraph/Twitter metadata, no metadataBase (Info / P3)
Social sharing will render no preview card.

### BUG-14 — Empty `next.config.ts` (Low / P3)
No headers, redirects, image config, or `poweredByHeader` tuning. (Overlaps BUG-01/BUG-11.)

### BUG-15 — No localization/`dir` scaffolding (Low / P3)
`lang="en"` present; no `dir`, no i18n strategy.

## 5. UX Improvement Suggestions
1. Replace scaffolding copy and default assets with real product content and branding.
2. Add responsive padding (`px-6 sm:px-16`, `py-12 sm:py-32`) so mobile is usable (BUG-05).
3. Add a real header/nav and footer with semantic landmarks (BUG-04).
4. Provide a manual light/dark theme toggle rather than relying only on OS preference.
5. Signal new-tab links to all users (icon + screen-reader text).
6. Add a skip-to-content link for keyboard users.

## 6. Security Findings
- **High:** No security headers (BUG-01). Add CSP, X-Frame-Options, HSTS, nosniff, Referrer-Policy, Permissions-Policy.
- **High:** 16 dependency vulnerabilities incl. 1 critical / 12 high (BUG-07). Remediate via `npm audit fix` and CI auditing.
- **Low:** `X-Powered-By` version disclosure (BUG-11).
- **No application-layer auth/session/token surface exists** to assess — flagged as a scope gap, not a passing security posture.

## 7. Accessibility Findings
- **Pass:** `lang="en"` set; single `<h1>`; images have meaningful `alt` text (`"Next.js logo"`, `"Vercel logomark"`); light-mode and dark-`zinc-400` contrast all exceed AA (7.7–21.0).
- **Fail/Risk:** base `zinc-600` on dark background = 2.56 (fails AA) if dark variant does not resolve (BUG-03); missing landmarks (BUG-04); no skip link (BUG-09); no new-tab cue (BUG-10).

## 8. Performance Findings
- **Excellent for current scope:** fully static prerender, TTFB ~2.6 ms, 12 KB HTML, long-lived cache, no runtime API calls, no layout-shift-inducing client fetches. Fonts loaded via `next/font` (self-hosted, no external request). SVG assets are small (128 B–1.4 KB).
- No raster images exist, so `next/image` optimization is effectively untested in practice; the optimizer rejects SVG with HTTP 400 (expected).
- Minor: empty `next.config.ts` means no explicit compression/header tuning (BUG-14).

---

## 9. Production Readiness Score

**42 / 100**

Rationale: The code that exists is clean (lint passes, build passes, strong performance, good base contrast and alt text). But the application is a **starter template with one placeholder page** and carries real production blockers: no security headers, a critical dependency vulnerability, placeholder metadata/content/branding, no semantic layout structure, and non-responsive mobile padding. It is not a shippable product.

## 10. Final Recommendation

### Needs Major Fixes

The repository is not a finished application; it is an unmodified Next.js starter. Before any production release it needs, at minimum:
1. Real product pages, content, and branding (replace all scaffolding).
2. Security headers and dependency remediation (BUG-01, BUG-07).
3. Semantic layout landmarks and responsive padding per the project steering (BUG-04, BUG-05).
4. Real metadata/SEO (BUG-02, BUG-13).

If the intent was only to validate the starter scaffold itself, it would be "Ready with Minor Fixes" (headers + audit). Judged as a product approaching production, the verdict is **Needs Major Fixes**.
