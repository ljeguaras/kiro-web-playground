### BUG-001 -- External Links Open in Same Tab (No `target="_blank"`)

**Severity:** Medium  
**Priority:** P2  
**Component:** Navigation Links -- "Templates" and "Learning" inline links

**Description:**  
The two inline text links in the main paragraph ("Templates" and "Learning") are external URLs but do not include `target="_blank"` or `rel="noopener noreferrer"`. This causes users to navigate away from the app without warning, losing their current context. The CTA buttons ("Deploy Now" and "Documentation") correctly use `target="_blank" rel="noopener noreferrer"`, making the behavior inconsistent.

**Steps to Reproduce:**  
1. Open the home page.
2. Click the "Templates" or "Learning" text link.
3. Observe: the browser navigates away from the current page.

**Expected Result:** External links should either open in a new tab (`target="_blank"`) with `rel="noopener noreferrer"` for security, or the behavior should be consistent across all external links.

**Actual Result:** "Templates" and "Learning" navigate in the same tab; "Deploy Now" and "Documentation" open in a new tab.

**Suggested Fix:**
```tsx
// In app/page.tsx, add target and rel to both inline links:
<a
  href="https://vercel.com/templates?..."
  target="_blank"
  rel="noopener noreferrer"
  className="font-medium text-zinc-950 dark:text-zinc-50"
>
  Templates
</a>
```

**Screenshot Reference:** N/A (logic issue, not visual)

### BUG-002 -- "Deploy Now" Link Lacks Descriptive ARIA Label

**Severity:** Medium  
**Priority:** P2  
**Component:** Accessibility -- CTA Link

**Description:**  
The "Deploy Now" button-link contains both an `<img alt="Vercel logomark">` and the text "Deploy Now". While this is technically accessible via the combined text content, screen readers will announce the image alt text followed by the link text, resulting in "Vercel logomark Deploy Now" rather than a clean "Deploy Now". No `aria-label` is set to override this.

**Steps to Reproduce:**  
1. Enable a screen reader (e.g., NVDA, VoiceOver).
2. Tab to the "Deploy Now" link.
3. Observe: the screen reader announces "Vercel logomark Deploy Now" instead of "Deploy Now".

**Expected Result:** Screen reader announces "Deploy Now" clearly.

**Actual Result:** Screen reader announces "Vercel logomark Deploy Now".

**Suggested Fix:**
```tsx
<a
  aria-label="Deploy Now on Vercel"
  className="..."
  href="..."
  target="_blank"
  rel="noopener noreferrer"
>
  <Image ... alt="" aria-hidden="true" />
  Deploy Now
</a>
```
(Set `alt=""` and `aria-hidden` on the decorative image, and add an `aria-label` on the link.)

### BUG-003 -- No Skip-Navigation Link

**Severity:** Medium  
**Priority:** P2  
**Component:** Accessibility -- Page Structure

**Description:**  
There is no skip-navigation link at the top of the page. Keyboard-only users and screen reader users must Tab through every interactive element (4 links) on every page load before reaching the main content area. For a starter template that is meant to be the base for larger applications, this is a significant accessibility gap.

**Steps to Reproduce:**  
1. Load the page.
2. Press Tab without clicking anywhere.
3. Observe: focus immediately goes to the first content link ("Templates") with no option to skip.

**Expected Result:** A visually hidden "Skip to main content" link should be the first focusable element.

**Actual Result:** No skip link is present.

**Suggested Fix:**  
Add to `app/layout.tsx` or `app/page.tsx`:
```tsx
<a
  href="#main-content"
  className="sr-only focus:not-sr-only focus:fixed focus:top-4 focus:left-4 focus:z-50 focus:px-4 focus:py-2 focus:bg-white focus:text-black"
>
  Skip to main content
</a>
```
Add `id="main-content"` to the `<main>` element.

### BUG-005 -- Excessive Padding on Very Small Mobile Screens

**Severity:** Low  
**Priority:** P3  
**Component:** Responsive Design -- Mobile Layout

**Description:**  
The `<main>` element uses `px-16` (64px per side = 128px total horizontal padding). On a 320px screen (Galaxy S4, older iPhone SE), this leaves only 192px of content width. The heading "To get started, edit the page.tsx file." at `text-3xl` (1.875rem) can only fit approximately 5-6 characters per line, causing extreme line wrapping. The CTA buttons with `h-12` height also appear very large relative to the narrow content area.

**Measured Values (Playwright DOM test at 320px viewport):**
- `mainWidth`: 320px
- `mainPaddingLeft`: 64px
- `mainPaddingRight`: 64px
- Available content width: 192px
- H1 rendered width: 192px

**Steps to Reproduce:**  
1. Load the page on a 320px wide viewport or device emulation.
2. Observe the heading text and CTA button layout.

**Expected Result:** Content should be readable with reasonable line lengths on narrow screens.

**Actual Result:** Heading wraps excessively; only ~6 characters fit per line.

**Suggested Fix:**
```tsx
// Change px-16 to px-4 sm:px-8 md:px-16 in app/page.tsx
<main className="... px-4 sm:px-8 md:px-16 ...">
```

### BUG-008 -- No Content Security Policy

**Severity:** Low  
**Priority:** P3  
**Component:** Security

**Description:**  
No Content Security Policy (CSP) is configured via either HTTP headers or a `<meta http-equiv="Content-Security-Policy">` tag. CSP is a critical security control that prevents XSS attacks by controlling which scripts, styles, and resources can be loaded. As the application grows to include user-generated content or third-party integrations, the absence of a CSP becomes a significant vulnerability.

**Steps to Reproduce:**  
1. Open browser DevTools > Network.
2. Inspect response headers for the HTML page.
3. Observe: no `Content-Security-Policy` header present.

**Suggested Fix:**  
Add CSP headers in `next.config.ts`:
```ts
const nextConfig: NextConfig = {
  async headers() {
    return [
      {
        source: '/(.*)',
        headers: [
          {
            key: 'Content-Security-Policy',
            value: "default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data:;"
          }
        ]
      }
    ];
  }
};
```

### BUG-009 -- No ARIA Labels on Interactive Elements

**Severity:** Low  
**Priority:** P3  
**Component:** Accessibility

**Description:**  
None of the 4 interactive links have explicit `aria-label` attributes. While the link texts ("Templates", "Learning", "Deploy Now", "Documentation") are generally descriptive, best practice dictates that links whose purpose might be ambiguous out of context should have `aria-label` attributes. The "Deploy Now" link is particularly at risk since its purpose depends on context (deploying to Vercel).

**Accessibility Tree Shows:**
```yaml
- link [ref=f10e14]: (no accessible name specified, derived from child content)
    - img "Vercel logomark"
    - text: "Deploy Now"
```

**Suggested Fix:**  
Add `aria-label` to links that benefit from additional context:
```tsx
<a aria-label="Deploy your Next.js app on Vercel" ...>
```

### BUG-013 -- Paragraph Link Color Has Limited Contrast Margin

**Severity:** Low  
**Priority:** P3  
**Component:** Accessibility -- Color Contrast

**Description:**  
The inline link text ("Templates", "Learning") uses `text-zinc-950` (`#09090b`, near-black) on a `text-zinc-600` paragraph. When these links are on a transparent background (which inherits from the white `<main>` background), the contrast ratio is ~21:1 -- excellent. However, the surrounding paragraph text `text-zinc-600` (`#52525c`) on white background has a contrast ratio of approximately 5.4:1 for normal text size, which narrowly passes WCAG AA (4.5:1 minimum) but fails WCAG AAA (7:1 minimum).

**Measured Contrast Ratios:**
- H1 (`text-black` on white): 21:1 -- WCAG AAA
- "Deploy Now" button (white on `#171717`): 17.93:1 -- WCAG AAA
- "Documentation" link (`#171717` on white): 17.93:1 -- WCAG AAA
- Body paragraph text (`text-zinc-600` = `#52525c` on white): ~5.4:1 -- WCAG AA only

**Suggested Fix:**  
For WCAG AAA compliance, change paragraph text to `text-zinc-700` or darker.

## 4. UX Improvement Suggestions

### UX-001 -- Add Visual Hierarchy Beyond Single H1
The page has only one heading level (H1). As the application grows, add H2 section headings for "Quick Start", "Resources", etc. to help users scan the page.

### UX-002 -- Improve CTA Button Differentiation
Both CTA buttons ("Deploy Now" and "Documentation") are the same height and width. Consider using different visual weights (primary vs. secondary styling) to guide users toward the primary action.

### UX-003 -- Add Loading States for External Navigation
When users click "Deploy Now" or "Documentation", there is no visual feedback before the new tab opens. For slower connections, adding a brief loading indicator or at minimum a pointer cursor (which is already set via `cursor=pointer`) is helpful.

### UX-004 -- Image Loading Optimization
The Next.js logo (`/next.svg`) uses `priority` loading (correctly), but the Vercel logomark inside the CTA button uses `loading="lazy"`. Since this image is in the initial viewport on all screen sizes, it should use `priority` to avoid lazy-load flicker.

### UX-005 -- Consistent Link Styling
The "Templates" and "Learning" links in the paragraph use `font-medium text-zinc-950` without underline (the CSS reset removes text-decoration from all anchors). Users may not immediately identify these as clickable links. Add hover or persistent underline styling to improve discoverability.

### UX-006 -- Mobile CTA Layout
On mobile (`< sm` breakpoint), the two CTA buttons stack vertically with `w-full` (full width). This is correct behavior, but the vertical gap between them is `gap-4` (16px) while the overall vertical rhythm uses `gap-6` (24px) elsewhere. Consider using `gap-6` throughout for visual consistency.

### UX-007 -- Dark Mode Logo Inversion
The `dark:invert` class on the Next.js logo SVG and Vercel logo creates a pure CSS inversion (hue-rotate), which changes colors based on the OS dark mode preference. This is functional but may produce unexpected color results on some SVGs. Consider providing separate dark-mode-specific logo variants.

### Bundle Analysis

The 626KB JavaScript total comes from the Next.js React Server Components runtime, React 19, the Turbopack-compiled client hydration code, and URL parsing polyfills (whatwg-url). For a static informational page, this is over-engineered. However, this is the standard Next.js framework overhead and is acceptable as a starting point.

**Recommendations:**
- Enable Gzip/Brotli compression on the web server (would reduce JS to ~180-200KB transfer size)
- Consider `next/font` optimization (already done for Geist fonts)
- The Vercel logomark `img` inside the CTA should use `priority` (not `loading="lazy"`) since it is in the initial viewport
