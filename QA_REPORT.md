### BUG-003 — No HTTP Security Headers

- **Severity:** High | **Priority:** P1  
- **Component:** `next.config.ts` (HTTP headers configuration)  
- **Description:** No security headers are configured. The application is missing:
  - `Content-Security-Policy` (XSS protection)
  - `Strict-Transport-Security` (HSTS — forces HTTPS)
  - `X-Frame-Options` (prevents clickjacking)
  - `X-Content-Type-Options` (prevents MIME sniffing)
  - `Referrer-Policy` (controls referrer information)
  - `Permissions-Policy` (restricts browser features)
- **Steps to Reproduce:**  
  1. Load the app and inspect response headers  
  2. Note complete absence of security headers  
- **Expected:** All standard security headers present  
- **Actual:** None of the above headers are set  
- **Suggested Fix:**  
  ```ts
  // next.config.ts
  const nextConfig: NextConfig = {
    async headers() {
      return [
        {
          source: '/(.*)',
          headers: [
            { key: 'X-Frame-Options', value: 'DENY' },
            { key: 'X-Content-Type-Options', value: 'nosniff' },
            { key: 'Referrer-Policy', value: 'strict-origin-when-cross-origin' },
            { key: 'Permissions-Policy', value: 'camera=(), microphone=(), geolocation=()' },
            {
              key: 'Strict-Transport-Security',
              value: 'max-age=63072000; includeSubDomains; preload',
            },
          ],
        },
      ];
    },
  };
  ```

### BUG-004 — Inline External Links Missing `target="_blank"` and `rel="noopener noreferrer"`

- **Severity:** Medium | **Priority:** P2  
- **Component:** `app/page.tsx` (lines 22 and 29)  
- **Description:** The "Templates" and "Learning" inline links are external links pointing to vercel.com and nextjs.org respectively, but they open in the same tab without `target="_blank"` or security `rel` attributes. This is inconsistent with the CTA buttons ("Deploy Now" and "Documentation") which correctly use `target="_blank" rel="noopener noreferrer"`. The missing `rel="noopener noreferrer"` on any `target="_blank"` links is also a security concern as it allows the opened tab to access the opener via `window.opener`.  
- **Steps to Reproduce:**  
  1. Click "Templates" link in the paragraph text  
  2. Observe it navigates away in the same tab  
- **Expected:** Consistent behavior — external links should either all open in new tabs or all open in same tab  
- **Actual:** "Templates" and "Learning" open in same tab; "Deploy Now" and "Documentation" open in new tab  
- **Suggested Fix:**  
  ```tsx
  <a
    href="https://vercel.com/templates?..."
    className="font-medium text-zinc-950 dark:text-zinc-50"
    target="_blank"
    rel="noopener noreferrer"
  >
    Templates
  </a>
  ```

### BUG-013 — Inline Links Not Visually Distinguishable from Body Text

- **Description:** The "Templates" and "Learning" inline links use `text-zinc-950` (near-black) on the same background as the body text. ## 4. UX Improvement Suggestions

### UX-001 — Add Underline/Hover Decoration to Inline Links

The "Templates" and "Learning" links in the paragraph text lack visible differentiation from body text. An underline using `underline underline-offset-2` would improve discoverability and UX.

### UX-002 — Provide Custom 404 Error Page

No custom `not-found.tsx` exists. The app falls back to Next.js's default 404 page which is unstyled and breaks the brand/design consistency.  
**Suggested Fix:** Create `app/not-found.tsx` with branded error content.

### UX-003 — Add Loading State

No `loading.tsx` exists. For future pages with data fetching, users would see a blank screen with no loading indicator.  
**Suggested Fix:** Create `app/loading.tsx` with a branded loading skeleton.

### UX-004 — Add a Custom Error Boundary

No `error.tsx` exists. Runtime errors would show an unstyled crash screen.  
**Suggested Fix:** Create `app/error.tsx` with a user-friendly error message and recovery action.

### UX-005 — Improve Link Contrast in Dark Mode

In dark mode, inline links use `text-zinc-50` (near-white) on a `dark:bg-black` background. While the contrast ratio is excellent (20:1), links are visually indistinguishable from surrounding paragraph text in dark mode since both use `dark:text-zinc-50`. The paragraph text also uses `dark:text-zinc-400` which is the same class but links override to `dark:text-zinc-50`. A visual differentiator (underline, different hue) would help.

### UX-006 — Add Apple Touch Icon for PWA-Readiness

No `apple-touch-icon` is defined. For users who add the app to their iOS home screen, a default icon will be displayed.

### UX-007 — Consistent CTA Link Behavior

The page has an inconsistency: two inline links open in the same tab; two CTA buttons open in new tabs. This creates unpredictable navigation behavior. Standardize all external links to either open in same-tab or new-tab with appropriate disclosure (e.g., screen reader text "opens in new tab").

### UX-008 — Consider Lazy Loading Vercel Logo Image

The Vercel logomark inside the "Deploy Now" CTA is loaded eagerly by default. Since it is below the fold on smaller viewports, adding `loading="lazy"` would be appropriate. (The Next.js logo at the top correctly uses `priority` to load eagerly, which is correct as it is above the fold.)

## 5. Security Findings

### SEC-001 — Missing HTTP Security Headers (Critical)

**Risk:** High  
The application has no HTTP security headers configured. This exposes users to:

| Missing Header | Risk |
|---------------|------|
| `Content-Security-Policy` | XSS attacks via injected scripts |
| `X-Frame-Options` | Clickjacking attacks — the app can be embedded in an iframe |
| `X-Content-Type-Options` | MIME type sniffing attacks |
| `Strict-Transport-Security` | Downgrade attacks — users may be served over HTTP |
| `Referrer-Policy` | UTM parameters and path information leaked to third parties |
| `Permissions-Policy` | Browser APIs (camera, mic, geolocation) not restricted |

**Recommendation:** Add security headers in `next.config.ts` as shown in BUG-003.

---

### SEC-002 — Inline External Links Missing `rel="noopener noreferrer"` on Potential `target="_blank"` Usage (Low)

**Risk:** Low  
The "Templates" and "Learning" links currently open in the same tab (no `target="_blank"`), so `rel` is not immediately critical. However, if `target="_blank"` is added in the future without `rel="noopener noreferrer"`, it would expose the app to reverse tabnapping attacks where the opened page can manipulate the original tab via `window.opener`.

**Recommendation:** Add `rel="noopener noreferrer"` to all external links regardless of `target` value, as a defensive measure.

---

### SEC-003 — No Content Security Policy in HTML Meta Tag (Medium)

**Risk:** Medium  
Without a CSP, any injected JavaScript (e.g., via a third-party script vulnerability) can execute with full page context. The application has no CSP in either HTTP headers or `<meta http-equiv="Content-Security-Policy">`.

---

### SEC-004 — No Source Maps in Production (Pass)

**Risk:** None  
Production build correctly excludes source maps. Attackers cannot easily reverse-engineer the application logic from minified bundles.

---

### SEC-005 — No Secrets Detected (Pass)

**Risk:** None  
No API keys, tokens, passwords, or sensitive values were found in the codebase. No `.env` files present (correct — `.env` is in `.gitignore`).

---

### SEC-006 — External Links Use `noopener noreferrer` (Pass — Partial)

**Risk:** Low  
The "Deploy Now" and "Documentation" CTAs correctly use `target="_blank" rel="noopener noreferrer"`, preventing reverse tabnapping for those links. However, as noted above, the inline links ("Templates", "Learning") do not have these attributes.
