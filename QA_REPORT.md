### BUG-001 — `X-Powered-By: Next.js` header exposes framework

**Severity:** High | **Priority:** P1  
**Component:** HTTP Response Headers

**Description:**  
Every HTTP response includes the header `X-Powered-By: Next.js`. This discloses the framework name and, combined with other signals, can reveal the exact version to attackers targeting known CVEs.

**Steps to Reproduce:**
1. Open a terminal
2. Run: `curl -sI http://localhost:3000 | grep X-Powered`
3. Observe `X-Powered-By: Next.js`

**Expected:** Header absent or suppressed  
**Actual:** `X-Powered-By: Next.js` present on all responses  

**Suggested Fix:**  
In `next.config.ts`:
```ts
const nextConfig: NextConfig = {
  poweredByHeader: false,
};
```

**Screenshot Reference:** N/A (HTTP header, text-based check)

### BUG-002 — No Content-Security-Policy header

**Severity:** High | **Priority:** P1  
**Component:** HTTP Response Headers

**Description:**  
No `Content-Security-Policy` (CSP) header is set. This leaves the page vulnerable to cross-site scripting (XSS) attacks and clickjacking via inline script injection or framing.

**Steps to Reproduce:**
1. `curl -sI http://localhost:3000 | grep -i "content-security"`
2. No output returned

**Expected:** `Content-Security-Policy` header present  
**Actual:** Header absent  

**Suggested Fix:**  
Add a CSP header via `next.config.ts` `headers()` function:
```ts
async headers() {
  return [{
    source: '/(.*)',
    headers: [
      { key: 'Content-Security-Policy', value: "default-src 'self'; img-src 'self' data:; font-src 'self'; script-src 'self'" }
    ]
  }]
}
```

### BUG-003 — No `X-Frame-Options` header (Clickjacking risk)

**Severity:** High | **Priority:** P1  
**Component:** HTTP Response Headers

**Description:**  
No `X-Frame-Options` or CSP `frame-ancestors` directive is configured. The page can be embedded in a malicious iframe for clickjacking attacks.

**Steps to Reproduce:**
1. `curl -sI http://localhost:3000 | grep -i "x-frame"`
2. No output

**Expected:** `X-Frame-Options: DENY` or `X-Frame-Options: SAMEORIGIN`  
**Actual:** Header absent  

**Suggested Fix:**  
Add `{ key: 'X-Frame-Options', value: 'SAMEORIGIN' }` to `next.config.ts` headers.

### BUG-004 — No `X-Content-Type-Options` header

**Severity:** High | **Priority:** P1  
**Component:** HTTP Response Headers

**Description:**  
The `X-Content-Type-Options: nosniff` header is absent. Browsers may perform MIME-type sniffing and execute a resource as a different MIME type than declared, enabling certain drive-by-download or content-injection attacks.

**Steps to Reproduce:**
1. `curl -sI http://localhost:3000 | grep -i "x-content-type"`
2. No output

**Expected:** `X-Content-Type-Options: nosniff`  
**Actual:** Header absent  

**Suggested Fix:**  
Add `{ key: 'X-Content-Type-Options', value: 'nosniff' }` to `next.config.ts` headers.

### BUG-005 — No Strict-Transport-Security (HSTS) header

**Severity:** High | **Priority:** P1  
**Component:** HTTP Response Headers

**Description:**  
No `Strict-Transport-Security` header is set. When deployed over HTTPS, the absence of HSTS allows downgrade attacks and prevents browsers from enforcing HTTPS-only connections.

**Steps to Reproduce:**
1. `curl -sI http://localhost:3000 | grep -i "strict-transport"`
2. No output

**Expected:** `Strict-Transport-Security: max-age=63072000; includeSubDomains; preload`  
**Actual:** Header absent  

**Suggested Fix:**  
Add `{ key: 'Strict-Transport-Security', value: 'max-age=63072000; includeSubDomains; preload' }` to `next.config.ts` headers. Only configure this for HTTPS environments.

### BUG-008 — External links open in new tab without screen-reader announcement

**Severity:** Medium | **Priority:** P2  
**Component:** Accessibility / `app/page.tsx`

**Description:**  
All four external links use `target="_blank"`. There is no visual icon or `aria-label` suffix to inform users (especially keyboard and screen reader users) that the link opens in a new tab. WCAG 2.1 Success Criterion 3.2.2 (On Input) and general usability guidelines recommend announcing this behavior.

**Steps to Reproduce:**
1. Focus any CTA link via keyboard Tab
2. Activate the link — a new tab opens without prior warning

**Expected:** Some indication (e.g. "(opens in new tab)" visually or via `aria-label`) that the link opens a new window  
**Actual:** No indication  

**Suggested Fix:**  
```tsx
<a target="_blank" rel="noopener noreferrer" aria-label="Deploy Now (opens in new tab)" ...>
  Deploy Now
</a>
```
Or append `<span className="sr-only"> (opens in new tab)</span>` inside each link.

### BUG-011 — Vercel logomark aspect ratio mismatch triggers Next.js Image warning

**Severity:** Medium | **Priority:** P2  
**Component:** Performance / Image / `app/page.tsx`

**Description:**  
The Vercel SVG (`/vercel.svg`) has a `viewBox="0 0 1155 1000"` — an aspect ratio of approximately 1.155:1. The Next.js `<Image>` component is given `width={16} height={16}` (1:1 ratio). This causes Next.js to emit the console warning:

> "Image with src 'http://localhost:3000/vercel.svg' has either width or height modified, but not the other. If you use CSS to change the size of your image, also include the styles 'width: auto' or 'height: auto' to maintain the aspect ratio."

The rendered image will appear squashed vertically.

**Steps to Reproduce:**
1. Start dev server: `bun run dev`
2. Open browser devtools console
3. Observe warning from Next.js Image component

**Expected:** Image renders at correct aspect ratio with no console warning  
**Actual:** Squashed 1:1 rendering; console warning emitted  

**Suggested Fix:**  
Either:
- Set `height={Math.round(16 * 1000 / 1155)}` = `height={14}` to match the viewBox ratio, or
- Use `width={16} height="auto"` with appropriate CSS

```tsx
<Image
  src="/vercel.svg"
  alt="Vercel logomark"
  width={16}
  height={14}  // corrected for 1155:1000 viewBox ratio
  className="dark:invert"
/>
```

### BUG-012 — Vercel logo inside CTA button is lazy-loaded (above the fold)

**Severity:** Medium | **Priority:** P2  
**Component:** Performance / Image / `app/page.tsx`

**Description:**  
The Vercel logomark inside the "Deploy Now" CTA button is rendered with `loading="lazy"` (which is what Next.js `<Image>` defaults to when `priority` is not set). Since this image is above the fold, lazy-loading defers its fetch and can cause a brief flash of empty space inside the CTA button.

**Steps to Reproduce:**
1. `curl -s http://localhost:3000 | grep "vercel.svg"`
2. Observe `loading="lazy"` in rendered `<img>` element

**Expected:** Above-the-fold images use `priority` or `loading="eager"`  
**Actual:** `loading="lazy"` on above-the-fold CTA button icon  

**Suggested Fix:**  
```tsx
<Image
  src="/vercel.svg"
  alt="Vercel logomark"
  width={16}
  height={14}
  priority  {/* add this */}
/>
```

### BUG-016 — `globals.css` body font-family override conflicts with Geist font variable

**Severity:** Low | **Priority:** P3  
**Component:** CSS / Typography / `app/globals.css`

**Description:**  
`globals.css` includes:
```css
body {
  font-family: Arial, Helvetica, sans-serif;
}
```
This direct override on `body` takes precedence over the Tailwind `font-sans` utility class (which maps to `--font-geist-sans`). As a result, the Geist Sans font loaded from Google Fonts (`@next/font/google`) is applied to the `<html>` element via CSS variables, but the body fallback renders in Arial unless an element explicitly adds `className="font-sans"`.

**Steps to Reproduce:**
1. Open `app/globals.css`
2. Observe `body { font-family: Arial, Helvetica, sans-serif; }`
3. Load page in browser with devtools — computed font for `<p>` is Arial, not Geist

**Expected:** Body font is Geist Sans (matching the CSS variable `--font-geist-sans`)  
**Actual:** Body font is Arial due to direct override  

**Suggested Fix:**  
Remove the hardcoded `font-family` from `body` and rely on the Tailwind CSS variable:
```css
body {
  background: var(--background);
  color: var(--foreground);
  /* Remove: font-family: Arial, Helvetica, sans-serif; */
}
```
The page component already uses `className="font-sans"` on the outer div which correctly picks up the Geist variable.

### BUG-017 — Responsive gap between `sm` and `md` breakpoints for CTA buttons

**Severity:** Low | **Priority:** P3  
**Component:** Responsive Design / `app/page.tsx`

**Description:**  
CTA buttons use `w-full` on mobile and jump to `md:w-[158px]` (768px+). There is no handling for the `sm` to `md` range (640px - 767px). At these widths, buttons stack vertically (`flex-col` baseline) and are full-width. The `sm:flex-row` class switches to horizontal layout at 640px but the buttons remain at full width until 768px, causing them to be disproportionately wide horizontally.

**Steps to Reproduce:**
1. Open the page
2. Resize browser to a viewport width between 640px and 767px
3. Observe CTA buttons are full width in a horizontal row, appearing overly stretched

**Expected:** Buttons gracefully size to content or a reasonable max between `sm` and `md`  
**Actual:** Full-width buttons at horizontal layout (640-767px range)  

**Suggested Fix:**  
Consider adding `sm:w-auto` to allow buttons to size to content at the `sm` breakpoint, then fix the width at `md` if needed.

### BUG-018 — Static public assets have `max-age=0` cache headers

**Severity:** Low | **Priority:** P3  
**Component:** Performance / HTTP Caching

**Description:**  
The SVG files in `/public` (`/next.svg`, `/vercel.svg`) are served with `Cache-Control: public, max-age=0`. This means every page load revalidates these assets, adding unnecessary network round-trips. By contrast, Next.js correctly serves font files with `max-age=31536000, immutable`.

**Steps to Reproduce:**
1. `curl -sI http://localhost:3000/vercel.svg | grep Cache-Control`
2. Returns: `Cache-Control: public, max-age=0`

**Expected:** `Cache-Control: public, max-age=31536000, immutable` for static assets  
**Actual:** `Cache-Control: public, max-age=0`  

**Suggested Fix:**  
Configure `next.config.ts` headers to add long-lived cache headers for `/public` static assets, or move assets to the Next.js static asset pipeline which handles cache headers automatically.

### BUG-019 — `next.config.ts` missing production configuration; HMR cross-origin warning

**Severity:** Low | **Priority:** P3  
**Component:** Dev/Build Configuration / `next.config.ts`

**Description:**  
`next.config.ts` is entirely empty (no options set). In the current dev environment, Next.js emits:

1. A slow filesystem warning: "Slow filesystem detected. The benchmark took 243ms."
2. A blocked HMR request warning: "Blocked cross-origin request to Next.js dev resource /_next/webpack-hmr from 169.254.255.194."

The second warning occurs because the dev server's network IP is not added to `allowedDevOrigins`. While this does not affect production, it can cause hot-reload failures when accessing the dev server from a network IP.

**Steps to Reproduce:**
1. `bun run dev`
2. Access `http://169.254.255.194:3000` in a browser
3. Observe HMR connection is blocked; page changes do not hot-reload

**Expected:** `allowedDevOrigins` configured for the development network IP  
**Actual:** HMR blocked on network IP access  

**Suggested Fix:**  
```ts
const nextConfig: NextConfig = {
  poweredByHeader: false,
  allowedDevOrigins: ['169.254.255.194'],
};
```
